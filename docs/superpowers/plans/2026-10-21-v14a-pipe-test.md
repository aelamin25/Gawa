# v14a "Pipe test" implementation plan

> For agentic workers: executed inline in the chat that wrote it (superpowers:executing-plans). Steps use checkboxes.

**Goal:** Press the gear, speak Chinese, and Pengu answers out loud in Chinese (live OpenAI voice). The screen shows the
characters, the pinyin and a little English.

**Architecture:** A new sketch, `firmware/PenguCN/`; v13 in `firmware/Pengu/` stays untouched. The board connects to
`wss://api.openai.com/v1/realtime` through ESP-IDF's `esp_transport_ws` over TLS, using the built-in certificate bundle.
The pieces:
- a mic task streams 24 kHz PCM up
- a player task plays Pengu's audio from a PSRAM ring buffer
- the mic is muted while Pengu talks, so it can't hear itself
- after each reply, a second text-only request ("out of band") turns the characters into pinyin + English for the card

All JSON and base64 work lives in a pure C++ header (`rt_proto.h`). The Chinese font code (`cnfont.h`) and the screen
layout (`screen_cn.h`) are pure as well. That means all three are unit-tested or previewed on a PC before anything is
flashed.

**Tech stack:**
- arduino-cli 1.5, esp32 core 3.3.12, ArduinoJson 7.4
- esp_transport_ws + esp_crt_bundle from the core
- Noto Sans CJK SC turned into a 1-bit bitmap font by `tools/make_font.py` (GB2312 level 1 = 3,755 common characters,
  plus punctuation, ASCII and the tone-marked pinyin vowels)

**Deliberate v14a simplifications (back in v14):**
- No "Hey Pengu": ESP-SR stays off, so it can't clash with Wi-Fi/TLS memory, and v12's "silent after sr_start" bug is
  kept out of the test. The gear starts and ends a call.
- No tools or functions yet.
- No clock.

**Flash map:** unchanged from v13.
- app0 0x10000
- model 0x2F0000, unused in v14a
- 0x620000: renamed from `speech` to `font`, and holds `font.bin`

### Task 6: The live link (`live.h/.cpp`)

## What changed while building (21 Oct 2026)

**M's feedback during the build:**
- "Start super basic with the words." Pengu's brief now allows only about 20 basic words and replies of 2 to 6
  characters. It builds up one step per turn: 你好 → 我是Pengu → 你好吗/我很好 → 你叫什么名字 → 谢谢/不客气 →
  你喜欢鱼吗 → 再见.
- "Clearly readable." Two bigger font sizes were added: characters at 36 px and pinyin/English at 26 px whenever they fit
  on one line. 24 px and 20 px are kept for longer lines. `font.bin` is now 4 faces, 1.05 MB.
- "Keep Pengu center stage; fade between the three." This replaces Task 3's stacked layout:
  - Pengu stays full size.
  - One strip underneath shows the characters (4.5 s), then the pinyin (3.5 s), then the English (3 s), then round
    again.
  - A soft fade between them takes 3 quick updates: the old text in a 50% dot pattern, the new one at 50%, the new one
    solid.
  - Three dots show which part you are on. A new line from Pengu always starts on the characters, which match the voice.

**Fixes from the code review (Task 10):**
- **Critical:**
  - `ws_read_message` now polls first, then reads with long timeouts. This avoids an IDF 5.5.5 quirk where a server PING
    followed by a short read timeout desyncs the stream.
- **Important:**
  - OpenAI answers 101 even for a bad key, then sends an `error` event. The error code now maps to BAD KEY, NO CREDIT?
    or MODEL?, and it is shown when the link closes.
  - The TLS transport is now freed on every path. Before, it leaked about 40 KB per call.
  - The buttons have their own task, so a click during an e-paper update is never missed.
  - There is a clean full refresh during long calls.
  - Cards carry a sequence number, so a late card is never shown under a new line.
  - "NO ANSWER" after 15 s if the session never starts.
  - A call can't start without the font; it shows "NO FONT" instead of crashing.
- **Minor:**
  - The mic opens only after the greeting.
  - The mic side is locked once heard.
  - Hanging up is instant on screen.
  - The audio copy happens outside the spinlock.
  - Empty strip parts are skipped.
  - The view is cleared before a call.
  - The greeting carries the full persona.
- **Still to watch on the board:** IDF's 1 KB buffer for the upgrade reply headers. The reviewer measured 768 bytes with
  an auth header. If the log shows "Header size exceeded buffer size", the upgrade has to be written by hand.
